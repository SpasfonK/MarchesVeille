1. Présentation et concepts

MarchesVeille est une application Windows autonome : un seul fichier MarchesVeille.exe sans runtime .NET à installer. Elle télécharge, dédoublonne et indexe localement les avis de marchés publics, puis permet de retrouver, qualifier et archiver les dossiers de consultation (DCE) — sans compte, sans cloud.

Flux de travail général

  1. Synchroniser les avis depuis les portails (BOAMP, PLACE, Grand Est, profils personnalisés).
  2. Rechercher / filtrer dans la base locale (plein texte instantané, filtres rapides, veilles).
  3. Qualifier automatiquement : type de marché (Travaux/Fournitures/Services/PI) et tags (ex. VNF-DTNE).
  4. Collecter les DCE de façon anonyme selon des profils, et les archiver sous DCE/.
  5. Retrouver une archive par recherche dans les avis, les noms de fichiers et le contenu des documents.

Ce que fait l'application, en une phrase par fonction

  • Recherche plein texte FTS5 : mots, "phrase exacte", AND/OR/NOT, insensible aux accents et à la casse, recherche instantanée.
  • Filtres rapides : région Grand Est, tag VNF DT Nord-Est, date limite à venir, non lus, favoris, curseur d'échéance, type de marché.
  • Signaux visuels : urgence rouge (≤ J-3), orange (≤ J-7), gris (clos), gras (non lu), marqueurs favori ★ et DCE 📦.
  • Veilles programmées : enregistrez un jeu de filtres, l'appli compte les nouveaux avis depuis la dernière consultation.
  • Connecteurs : BOAMP (API JSON), PLACE et Région Grand Est (HTML), plus vos profils via connectors.json.
  • DCE anonyme : téléchargement sans identifiant via des parcours configurables, classement dans DCE/AAAA/MM/<acheteur>/….
  • Archives indexées : avis + noms de fichiers + texte des PDF/Office ; recherche avancée multi-critères.
  • Mode batch : --scrap et/ou --dce pour l'automatiser (Planificateur de tâches).
Hors-ligne par conception Une fois les avis synchronisés et les DCE archivés, tout reste consultable sans connexion : la base SQLite (marches.db) et le dossier DCE/ contiennent l'intégralité des données et des documents.

2. Installation et premier lancement

Obtenir l'application

  1. Depuis la CI GitHub : ouvrez l'onglet Actions du dépôt, sélectionnez le dernier build vert, puis téléchargez l'artefact MarchesVeille-win-x64 (contient MarchesVeille.exe).
  2. Compilation locale (Windows + SDK .NET 8) : 
    dotnet test   tests/MarchesVeille.Tests/MarchesVeille.Tests.csproj -c Release
dotnet publish src/MarchesVeille.Desktop/MarchesVeille.Desktop.csproj -c Release -r win-x64 --self-contained true -o publish
    Le résultat est publish/MarchesVeille.exe (exécutable unique auto-suffisant).

Lancement

  • Sans argument : double-cliquez MarchesVeille.exe → l'interface graphique s'ouvre.
  • Avec arguments (voir §15) : l'application s'exécute en batch, sans fenêtre, et écrit dans la console et dans marches-scrap.log.

Emplacement des données Par défaut tout est écrit à côté de MarchesVeille.exe (dossier portable, clé USB possible). Si ce dossier n'est pas inscriptible (ex. C:\Program Files), l'appli bascule automatiquement sur %LOCALAPPDATA%\MarchesVeille. Voir §17.
Bibliothèque SQLite embarquée La bibliothèque native SQLite est incluse dans l'exécutable et extraite dans le dossier temporaire au démarrage : aucune installation supplémentaire n'est nécessaire.

3. Interface principale

La fenêtre Veille Marchés Publics se compose de quatre zones :

  • Barre de recherche (haut) : champ de recherche instantané + sélecteur de Tri.
  • Filtres rapides : boutons bascules et curseurs d'affinage.
  • Résultats (tableau à gauche) et panneau latéral à onglets (à droite : Détail et Veilles programmées).
  • Barre de synchronisation (bas) : choix de la source, des jours, option DCE, boutons de collecte et d'archives.

Découverte guidée (première utilisation)

  1. Choisissez une Source et un nombre de Jours, puis cliquez Lancer la synchronisation.
  2. Les avis apparaissent dans le tableau. Cliquez une ligne pour voir le Détail à droite (l'avis est alors marqué lu).
  3. Tapez un mot (ex. écluse) dans la recherche : le tableau se filtre instantanément.
  4. Cochez un filtre rapide (ex. Région Grand Est) pour affiner.
  5. Enregistrez ce filtre comme veille pour suivre les nouveaux avis au fil du temps.

4. La recherche plein texte (syntaxe)

Le champ de recherche interroge titre, description et acheteur via SQLite FTS5. La recherche est instantanée (débounce ~220 ms), insensible aux accents et à la casse, et tolère les requêtes mal formées (sans jamais planter).

Vous tapezEffet
ecluseMots contenant « écluse » (accents ignorés) ; préfixe inclus.
travaux ecluseLes deux termes (ET implicite selon la pertinence FTS).
"canal de la marne"Phrase exacte ; l'ordre des mots compte.
travaux AND ecluseLes deux présents.
ecluse AND NOT barrage« écluse » mais pas « barrage ».
papier OR travauxL'un ou l'autre.
Accents et préfixes ecluse trouve « ÉCLUSE ». eclu trouve « écluse » (recherche par préfixe).
Requête invalide Des saisies comme "travaux, ((), OR OR ou * sont neutralisées : la recherche ne renvoie simplement rien d'anormal, sans erreur.

Cliquez une ligne : le panneau Détail affiche le titre, les métadonnées (acheteur, référence, source, département, région, dates, tag) et la description. La sélection marque automatiquement l'avis comme lu.

Résultat du téléchargement DCE Le message d'état indique le cas : archivé (chemin affiché), accès restreint (une boîte propose d'utiliser « Accéder au DCE »), ou échec (motif affiché). Voir §13 pour les statuts.

7. Veilles programmées

Onglet Veilles programmées : enregistrez des jeux de filtres récurrents. Après chaque synchronisation, l'application calcule le nombre de nouveaux avis depuis votre dernière consultation.

  1. Configurez recherche + filtres (ex. « VNF travaux », région Grand Est).
  2. Cliquez Enregistrer le filtre courant et donnez un nom.
  3. La liste affiche Nom · N nouveau(x). Un compteur apparaît aussi dans l'onglet : Veilles programmées (N).
  • Appliquer (ou double-clic) : réapplique les filtres, relance la recherche et remet à zéro le compteur de nouveautés.
  • Supprimer : retire la veille.

8. Synchronisation des avis

Barre du bas :

  • Source : all ou un connecteur précis (boamp, place, grandest, ou un id personnalisé).
  • Jours : 1, 3, 7, 14 ou 31 (période de parution prise en compte).
  • puis télécharger les DCE : après la synchronisation, lance la collecte anonyme des DCE selon les profils actifs.
  • Lancer la synchronisation / Annuler : progression affichée source par source ; annulation immédiate possible.

En fin de synchronisation, un récapitulatif s'affiche (récupérés / nouveaux / doublons par source). Si une source échoue, une alerte liste les erreurs mais les autres sources restent ingérées. Après une synchronisation, les résultats et les compteurs de veilles sont rafraîchis automatiquement.

Dédoublonnage Un avis est identifié de façon stable par source + référence (empreinte SHA-256). Un avis déjà connu est mis à jour (nouveau titre, nouvelle échéance) sans perdre vos marques favori et lu.

9. Classification automatique (Travaux / Fournitures / Services / PI)

Chaque avis reçoit un type de marché :

  • Si la source le fournit (ex. BOAMP type_marche), cette valeur prime.
  • Sinon, il est déduit des motifs de la section classification de connectors.json (mots-clés « travaux », « fourniture », « services »…).
  • Une PI (prestation intellectuelle : études, maîtrise d'œuvre, AMO, audit, diagnostic, ingénierie…) est marquée IsPi = true et comptée aussi comme Service.

Le type apparaît dans la colonne Type (ex. Travaux · PI) et sert de filtre (interface, profils DCE, recherche avancée des archives).

Adapter le vocabulaire Éditez les listes travaux, fournitures, services, pi dans connectors.json (motifs sur texte sans accents, minuscules). Aucune recompilation : relancez l'application.

10. Qualification automatique par tag (VNF-DTNE…)

Les taggingRules posent un tag (buyer_category) sur les avis, par exemple VNF-DTNE. La première règle qui correspond l'emporte. Les motifs sont des expressions régulières appliquées à un texte sans accents et en minuscules.

{ "category": "VNF-DTNE",
  "buyerPatterns": ["voies navigables de france", "\\bvnf\\b"],
  "textPatterns":  ["direction territoriale nord[- ]?est", "\\bdtne\\b"],
  "sirets": ["13001840000012"] }
  • buyerPatterns / sirets : l'acheteur doit correspondre (si les deux sont vides, seul le texte est testé).
  • textPatterns : au moins un motif sur acheteur + titre + description.
  • Dans le JSON, doublez les antislashs : \\b, \\d.

Le tag alimente la colonne Tag, le filtre VNF DT Nord-Est et les profils de collecte.

Ajouter un profil acheteur sans recompiler

Ajoutez un objet dans customConnectors (un exemple désactivé est fourni) :

{
  "id": "mon-profil", "name": "Mon profil acheteur", "enabled": true,
  "baseUrl": "https://profil.example.org/",
  "searchUrl": "consultations/recherche",
  "formSelector": "form#recherche",
  "formFields": { "dateDebut": "{dateStart}", "dateFin": "{dateEnd}" },
  "submitName": "rechercher",
  "dateFormat": "dd/MM/yyyy",
  "rowSelector": "table#resultats tbody tr",
  "fields": {
    "reference": "td.ref", "title": "td.objet a", "buyer": "td.acheteur",
    "department": "td.dept", "deadline": "td.cloture",
    "url": "td.objet a@href", "dce": "td.dce a@href"
  },
  "paging": { "mode": "link", "nextSelector": "a.suivant" },
  "defaultRegion": "Grand Est",
  "keepBuyerPatterns": []
}

Le nouvel identifiant (mon-profil) apparaît dans la liste des Sources et s'utilise en CLI : --source=mon-profil.

Détail des champs d'un connecteur HTML

  • searchUrl : relatif à baseUrl (ou absolu) ; la page doit contenir le formulaire de recherche.
  • formSelector : sélecteur CSS du formulaire ; tous ses champs (champs cachés PRADO_PAGESTATE, __VIEWSTATE…) sont repris automatiquement.
  • formFields : champs à forcer (nom → valeur). Jetons : {dateStart}, {dateEnd} (selon dateFormat), {isoStart}, {isoEnd}. La période couvre --days jours, aujourd'hui inclus.
  • submitName : nom du bouton de recherche. Si postbackTargetField est renseigné (ex. PRADO_POSTBACK_TARGET), la valeur est postée dans ce champ (postback Prado) ; sinon submitName=1 est posté comme un bouton.
  • rowSelector : une ligne de résultat. fields : "sélecteur CSS" (texte) ou "sélecteur CSS@attribut" (ex. a@href). Clés reconnues : reference, title, description, buyer, department, publication, deadline, url, dce.
  • paging.mode : none, link (suit le href de nextSelector) ou postback (reposte le formulaire). Arrêt automatique quand une page n'apporte aucun nouvel avis ou que maxPages est atteint.
  • keepBuyerPatterns : si non vide, seuls les avis dont l'acheteur correspond sont conservés (filtre côté client).
  • Les dates sont lues en heure de Paris et stockées en UTC.

BOAMP

  • keepDepartments / keepBuyerPatterns : un avis est conservé s'il est dans un de ces départements ou si l'acheteur correspond (par défaut : Grand Est + VNF). Les deux listes vides = tout conserver.
  • extraWhere : clause ODSQL ajoutée côté serveur (optionnel).
  • Requête paginée par jour de parution ; la limite Opendatasoft (offset + limit ≤ 10 000) est respectée.
Sélecteurs PLACE / Grand Est à valider Les sélecteurs et noms de champs fournis pour place et grandEst sont des valeurs de départ non vérifiées sur les sites réels. Le connecteur BOAMP (API JSON) est le plus fiable et couvre déjà une grande partie des avis PLACE et VNF.

Trouver les bons sélecteurs

  1. Ouvrez le portail, outils de développement (F12), onglet Réseau.
  2. Lancez une recherche : repérez la requête POST et les noms de champs envoyés → formFields, submitName.
  3. Onglet Éléments : clic droit sur une ligne de résultat → Copier → sélecteur CSS → rowSelector, puis fields.
  4. Testez : MarchesVeille.exe --scrap --source=mon-profil --days=1 puis lisez marches-scrap.log.

12. Profils de collecte DCE

Bouton Collecte DCE… : fenêtre de gestion des profils qui déterminent quels DCE télécharger.

Critères d'un profil

Un avis est retenu s'il satisfait tous les critères renseignés d'un profil actif (un critère multiple est satisfait par l'un de ses éléments) :

  • Mots-clés (objet, description, acheteur) et mots-clés à exclure (un par ligne) ;
  • Organisations (fragment de nom, ex. « voies navigables ») ;
  • Types de marché : Travaux / Fournitures / Services / PI (aucun coché = tous) ;
  • Régions (ex. Grand Est) et Tags (ex. VNF-DTNE).
Règles clés Un profil sans aucun critère télécharge tout. Les profils sont stockés dans marches.db. Plusieurs profils actifs se cumulent (OU). En ligne de commande, --dce-all ignore les profils.

Fenêtre « Collecte des DCE »

  • Liste des profils à gauche (● actif / ○ inactif, mention « (tout) » si sans critère) ; Nouveau, Supprimer.
  • Éditeur à droite : nom, case « Profil actif », champs de critères, bouton Enregistrer le profil.
  • Bas : Avis publiés depuis N jours (15/31/45/90/180/365), Réessayer les accès restreints / non pris en charge, Mode diagnostic, bouton Lancer la collecte (et Annuler), barre de progression et journal détaillé.

Réglages de collecte (connectors.json, section dce)

CléRôle
folderDossier des archives (relatif à l'exe, ou absolu). Défaut : DCE.
maxFileSizeMbTaille maximale d'un DCE (au-delà : échec, rien n'est conservé). Défaut 500.
maxPerRunNombre maximal de DCE par exécution ; le reste est repris au lancement suivant. Défaut 300.
delayMsPause entre deux téléchargements. Défaut 1500 ms.
maxAttemptsTentatives avant abandon d'un DCE en échec. Défaut 3.
publishedWithinDaysSeuls les avis publiés depuis N jours sont candidats. Défaut 45.

13. Téléchargement anonyme des DCE (parcours portail)

Chaque connecteur HTML décrit, dans sa section dce, comment atteindre le fichier anonymement, sous forme d'étapes exécutées dans une même session :

"dce": {
  "enabled": true,
  "steps": [
    { "type": "get",  "url": "{dceUrl}" },
    { "type": "link", "selector": "a[href*='TelechargementDce']" },
    { "type": "form", "formSelector": "form", "fields": { "choix": "anonyme" },
      "submitName": "valider", "postbackTargetField": "PRADO_POSTBACK_TARGET", "optional": true },
    { "type": "link", "selector": "a[href*='DownloadCompleteDce']" }
  ],
  "restrictedPatterns": ["identifiez-vous", "mot de passe"]
}
  • get : ouvre une URL ({dceUrl} = lien du DCE s'il est connu, sinon {noticeUrl} = page de l'avis).
  • link : suit le premier lien correspondant au sélecteur CSS de la page courante.
  • form : soumet un formulaire de la page courante (champs cachés repris, fields forcés). Aucune coordonnée n'est envoyée : seuls les champs que vous configurez le sont.
  • optional : l'étape est ignorée si l'élément est absent. Le parcours s'arrête dès qu'une réponse est un fichier (zip, pdf…).
  • Sans steps, le lien {dceUrl} est téléchargé directement.
  • Si le parcours finit sur une page HTML contenant un des restrictedPatterns, l'archive est marquée restricted.
  • Un avis BOAMP est traité par le connecteur dont l'adresse correspond à l'URL du DCE trouvée dans l'avis.

Rangement et statuts

Les archives sont rangées sous DCE/AAAA/MM/<acheteur>/<référence>_<objet>.zip.

StatutSignification
okTéléchargé et archivé.
failedÉchec ; réessayé jusqu'à maxAttempts.
restrictedIdentification ou inscription exigée ; non retenté sauf option dédiée.
unsupportedAucun connecteur pour ce portail ; non retenté sauf option dédiée.

restricted et unsupported ne sont retentés qu'avec l'option « Réessayer les accès restreints / non pris en charge » (interface) ou --dce-retry (CLI).

Mode diagnostic Cochez Mode diagnostic (ou --dce-debug) : les pages HTML de chaque étape sont sauvegardées dans DCE/_diagnostic/<avis>/etapeN.html. Ouvrez-les pour corriger sélecteurs et noms de champs, relancez, jusqu'à obtenir un zip.

Usage typique

  • Interface : Jours = 31, case puis télécharger les DCE, Lancer la synchronisation.
  • CLI : MarchesVeille.exe --scrap --days=31 --dce.

14. Archives DCE : recherche et exploitation

Bouton Archives DCE… : interroge l'index des archives sans limite de date de récupération.

Barre de recherche + « Chercher dans »

  • Mêmes mots, "phrase exacte", AND/OR/NOT, insensible aux accents et à la casse.
  • Chercher dans : Tout, Avis (objet, acheteur, référence), Noms de fichiers, Contenu des documents.

Recherche avancée

  • Organisation, Référence, Type (Travaux/Fournitures/Services/PI), Région (Toutes/Grand Est).
  • Dates de publication (du / au) et dates de récupération (du / au).
  • Tri : Pertinence, Publiés récemment, Récupérés récemment. Bouton Réinitialiser.

Tableau et panneau de détail

  • Colonnes : Publié, Acheteur, Objet (surligné), Type, Fichiers (nombre), Taille, Récupéré.
  • Détail : métadonnées, extrait de contenu surligné, et liste des fichiers contenus dans l'archive.
  • Actions : Ouvrir l'archive (double-clic aussi), Afficher dans le dossier (sélectionne le fichier dans l'Explorateur), Ouvrir l'avis.
Contenu indexé PDF avec couche texte, Word (docx), Excel (xlsx), PowerPoint (pptx), LibreOffice (odt/ods/odp), txt/csv/xml/html, et zips imbriqués (2 niveaux). Les PDF scannés (images) ne sont pas lisibles : seuls leurs noms de fichiers sont indexés (pas d'OCR). Les archives restent trouvables même si l'avis a disparu de la base : l'index copie les informations de l'avis.

Exemples

# Veille quotidienne (3 derniers jours, toutes les sources)
MarchesVeille.exe --scrap --source=all --days=3

# Collecte mensuelle des avis et des DCE
MarchesVeille.exe --scrap --days=31 --dce

# Reprendre uniquement la collecte des DCE restants
MarchesVeille.exe --dce-only

# Diagnostic des sélecteurs sur quelques DCE
MarchesVeille.exe --dce-only --dce-all --dce-max=3 --dce-debug

Le journal est écrit dans marches-scrap.log à côté de la base (et affiché dans la console si elle est attachée).

16. Planification automatique (Planificateur de tâches)

  1. Ouvrez le Planificateur de tâches Windows → Créer une tâche.
  2. Action : Démarrer un programme → MarchesVeille.exe.
  3. Arguments : --scrap --source=all --days=3 (quotidien) ou --scrap --days=31 --dce (mensuel).
  4. Déclencheur : quotidien/hebdomadaire/mensuel selon votre besoin.
Bon réflexe Cochez « Exécuter même si l'utilisateur n'est pas connecté » si la tâche doit tourner sans session ouverte. Le code de sortie et le journal marches-scrap.log permettent de surveiller l'exécution.

18. Anonymat et respect des plateformes

  • Un téléchargement anonyme reste visible de l'acheteur dans les statistiques de la plateforme (nombre de retraits), sans nom.
  • Respectez les conditions d'utilisation : gardez des pauses raisonnables (delayMs, requestDelayMs) et des volumes mesurés (maxPerRun).
  • Pour une consultation sous le seuil de publicité obligatoire ou réservée, le portail peut exiger une inscription : l'archive sera restricted et le bouton Accéder au DCE vous permet de la récupérer dans votre navigateur.
  • Aucune donnée n'est envoyée à un serveur tiers : tout est traité et stocké en local.

20. Raccourcis et bonnes pratiques

  • Entrée dans la recherche : relance immédiatement (sans attendre le débounce).
  • Double-clic sur une veille : l'applique. Double-clic sur une archive : l'ouvre.
  • Utilisez le Tri « Échéance proche » pour traiter les urgences en premier.
  • Enregistrez des veilles par thème (VNF travaux, Grand Est fournitures, PI études) plutôt qu'une seule veille fourre-tout.
  • Pour la collecte DCE, préférez des profils ciblés à « tout télécharger », pour limiter le volume et rester courtois.
  • Faites une sauvegarde périodique de marches.db et DCE/.
  • Sur une nouvelle version, remplacez l'exe ; la base et la configuration sont conservées.
